# Quickstart & Validation Guide: 浏览器书签双向同步插件

**Feature**: `001-bookmark-sync` | **Date**: 2026-10-27

本指南只描述"如何跑起来并证明它满足规格"，不包含实现代码。合并规则见 [data-model.md](./data-model.md)，接口细节见 [contracts/relay-protocol.md](./contracts/relay-protocol.md)。

## 2. 步骤 0：验证 ego 能加载本地扩展（硬门槛）

这一步失败则整个浏览器扩展路线不成立，必须先处理再继续。

1. 打开 ego lite，进入扩展管理页（`chrome://extensions` 或 ego 对应入口）。
2. 确认"开发者模式"可开启。
3. 用任意最小 MV3 扩展（`manifest.json` + 空 Service Worker）执行"加载已解压的扩展程序"。
4. 确认扩展出现在列表中且 Service Worker 能启动。

**通过标准**: 扩展成功加载，`chrome.bookmarks` 权限被接受（可在扩展详情中看到权限）。

**失败处理**: 记录 ego 的版本与扩展页表现，切换到"文件桥接"方案（关闭浏览器时读写 `Bookmarks` JSON）；`core` 合并引擎无需改动。

> 参考路径：ego 的用户数据位于 `C:\Users\CL\AppData\Local\Citro Labs\ego lite\User Data\Profile 1..4`，每个 Profile 都有自己的 `Bookmarks` 文件。

## 3. 构建与启动

以下命令对应计划中的 npm workspaces（`core` / `extension` / `relay`）：

```powershell
# 安装依赖
npm install

# 构建扩展（输出 extension/dist）与中继
npm run build

# 启动本机中继（首次启动会生成令牌）
npm run relay
```

首次启动中继后：

- 控制台会打印一次令牌；
- 令牌同时写入 `relay/data/token.txt`；
- `GET http://127.0.0.1:8787/health` 返回 `{"status":"ok", ...}`。

**端口被占用时**：设置 `RELAY_PORT` 环境变量（例如 `$env:RELAY_PORT=8788`），并同步修改扩展设置中的地址。

## 4. 安装扩展

### 4.1 Chrome

1. 打开 `chrome://extensions`，开启"开发者模式"。
2. "加载已解压的扩展程序" → 选择 `extension/dist`。
3. 打开扩展的"选项"页：
   - 中继地址：`ws://127.0.0.1:8787/ws`
   - 令牌：粘贴 `relay/data/token.txt` 内容
   - 端点名称：`chrome-default`
4. 点击"测试连接"，应显示"已连接"。

### 4.2 ego lite

1. 切换到准备参与同步的**那一个 Profile**（本机有 Profile 1–4；v1 只同步选中的这个，本机实际使用 `Profile 4`）。
2. 进入扩展管理页，开启"开发者模式"。
3. 加载 `extension/dist`。
4. 在选项页填入相同的中继地址与令牌，Profile 名称填 `ego`（本机实际值）。
5. 不要在其他 ego Profile 中安装本扩展；即使安装，也不要在其中填写令牌。

> 扩展天然按 Profile 隔离：每个 Profile 的 `chrome.bookmarks` 只能看到自己的书签。

---

## 5. 首次配对（含预演与备份）

1. 在两端分别打开扩展弹窗，点击"开始配对"。
2. 扩展会收集本端书签树并发送 `push`（`dryRun: true`）。
3. 弹窗展示预览：将新增 / 合并 / 删除 / 冲突的条目数量。
4. **先备份**：
   - 中继在提交前写入 `relay/data/backup-<时间戳>.json`；
   - 扩展提供"导出当前书签"按钮，生成可恢复的 JSON 文件。
5. 确认无误后点击"确认合并"，扩展发送 `commit`。
6. 等待两端显示"同步完成"，对比书签栏与其他书签。

**预期**: 两端书签是并集；没有任何一端的现有书签被删除；重复内容合并为一条。

## 6. 验收场景

每个场景都对应规格中的用户故事与成功标准。操作后等待扩展显示"已同步"（通常 ≤ 10 秒）再检查。

### V1 — 两端各自新增，合并后都保留（US1 / SC-001）

1. 在 ego 的书签栏新增书签 `A`（例如 `https://example.com/a`）。
2. 在 Chrome 的书签栏新增书签 `B`（例如 `https://example.com/b`）。
3. 等待同步完成。
4. 检查两端：书签栏应同时包含 `A` 与 `B`，每个各一份。

**通过标准**: 两端集合一致，无重复（重复率 0）。

### V2 — 删除传播且不复活（US2 / SC-002）

1. 确保两端都有书签 `A`。
2. 在 Chrome 删除 `A`。
3. 等待同步；ego 中 `A` 应消失。
4. 在两端各手动触发 10 次同步（或等待 10 个同步周期）。
5. 检查 `A` 没有重新出现。

**通过标准**: 删除在 10 秒内传播；连续 10 次同步后不复活。

### V3 — 文件夹、改名、移动（US3 / SC-003）

1. 在 ego 新建 `工作/项目/资料` 三层文件夹，并把书签放入最内层。
2. 同步后检查 Chrome 的层级与书签归属完全一致。
3. 在 Chrome 将 `资料` 重命名为 `归档`。
4. 在 ego 将一条书签从 `项目` 移动到 `书签栏`。
5. 同步后检查：重命名与移动都跟随，且没有产生副本。

**通过标准**: 结构一致率 100%，副本数 0。

### V4 — 规模（SC-004）

1. 准备一个包含 1,000 条书签、5 层文件夹结构的 HTML 书签文件。
2. 在 Chrome 导入该文件；ego 保持为空（或反之）。
3. 记录首次合并耗时。
4. 比对两端节点数量与路径集合。

**通过标准**: 60 秒内完成；两端结构与内容一致率 100%。

### V5 — 断线恢复（SC-006）

1. 停止中继（`Ctrl+C`）。
2. 在 Chrome 新增 `C1`，在 ego 新增 `E1`。
3. 两端界面应显示"未连接"，浏览器本身仍可正常使用。
4. 重新启动中继。
5. 等待自动重连与补偿同步。

**通过标准**: 5 分钟内两端都包含 `C1` 与 `E1`；丢失 0、重复 0。

### V6 — 回环与抖动（SC-005）

1. 两端保持在线，连续操作 1 小时（可脚本化：每 30 秒在一端新增或移动一条）。
2. 记录两端的书签总数变化曲线。
3. 结束时检查同步次数与 `seq` 增长。

**通过标准**: 总数不因同步产生额外副本；无同步风暴（空闲时 `seq` 不增长）；重复率 0。

### V7 — 冲突按后到者胜并收敛（FR-006 / SC-007）

1. 确保两端都有书签 `X`。
2. 断开中继；在 Chrome 删除 `X`；在 ego 将 `X` 改名并移动。
3. 恢复中继并同步。
4. 检查结果：两端最终状态一致——若删除先到，`X` 复活；若改名先到，`X` 被删除。扩展状态中应出现 `delete_vs_edit` 冲突记录。

**通过标准**: 两端最终一致（都有或都没有 `X`）；冲突在界面可见。

### V8 — 多 Profile 隔离（FR-010）

1. 只在 ego 的 `Profile 4` 安装并配置扩展（本机实际使用的同步 Profile）。
2. 在 `Profile 4` 新增书签。
3. 切换到另一个 Profile（例如 `Profile 3`），检查其书签未被读取或改动。
4. 检查中继状态中的端点只包含本机 ego 的那个端点（浏览器 `ego`）。

**通过标准**: 未选中的 Profile 书签零变化。

## 8. 回滚与恢复

- **中继备份**: `relay/data/backup-<时间戳>.json`，默认保留最近 5 份。
- **扩展导出**: 弹窗"导出当前书签"生成的 JSON 可通过 Chrome/ego 的书签导入功能恢复。
- **回滚步骤**:
  1. 暂停两端同步；
  2. 用备份文件恢复其中一端的书签；
  3. 清除扩展的本地映射与基线（设置页"重置同步状态"）；
  4. 重新配对（预演 → 确认）。
- **注意**: 直接删除 `relay/data/state.json` 会让墓碑丢失，可能导致已删除书签复活；恢复前先确认两端书签状态。

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| 扩展显示"未连接" | 中继是否启动；端口是否为 8787；令牌是否一致；`/health` 是否可达 |
| 同步后出现重复 | 检查两端是否使用了不同令牌导致两个端点身份；检查首次配对是否走了预演 |
| 删除后书签又回来 | 检查是否有未 `ack` 的端点仍在推送旧树；确认墓碑未在该端点确认前被清理 |
| ego 中看不到扩展 | 回到步骤 0，确认扩展页与开发者模式；确认安装到了目标 Profile |
| 同步频繁抖动 | 查看 Service Worker 日志中的 `loop-guard` 命中；确认基线在应用远端变更后已推进 |
| 首次合并卡住 | 检查快照大小是否接近 8 MiB；1,000 条书签应在 60 秒内完成 |
